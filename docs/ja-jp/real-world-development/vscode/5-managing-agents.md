GitHub Copilot をエージェント モードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、作業が自分のマシンでリアルタイムに進むため、ツールの呼び出しやファイルの編集を確認できます。差分をインラインでレビューし、個々の変更を承認または却下できます。また、エディターを離れずに追加のプロンプトを送って会話の方向を調整し、作業を改善または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして承認します。
- セッション中にエージェントへ指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、ハイ コントラスト モードを実装中です。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいと依頼がありました。新しい会話を始める代わりに、既存のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案する編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み込みや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントが編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、セッション中に変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツールの許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドのみ承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。変更の概要を示す最終メッセージが表示されます。

## エージェントにライト モードを追加するよう依頼する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けるため、エージェントは前の作業で変更したコンポーネント、スタイルの方針、local storage の使用方法を含むコンテキストを保持しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライト モードの追加を提案します。
3. ハイ コントラスト モードの場合と同様に、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方針（たとえば、好みと異なる方法で切り替え UI をリファクタリングするなど）に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> 実行中のセッションに追加の指示を送ると、最初からやり直すより早く進められます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを組み込む」「両方の切り替えにキーボード ショートカットも追加する」など、調整、軌道修正、範囲の拡張を依頼できます。

## 変更一式をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル全体を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ パターン（ARIA 属性、キーボード ナビゲーション、セマンティック HTML、local storage による保存）が反映されていることを確かめます。
4. 問題がなければ Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視して方向を調整しました。ファイルの編集を確認し、変更を承認または却下し、コンテキストを失わずに作業を拡張する追加プロンプトを送信しました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または却下しました。
- 追加プロンプトを使って、実行中のセッションの方向を調整しました。
