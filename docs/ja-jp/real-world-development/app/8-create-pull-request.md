フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。これらをまとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にマージの作業を任せます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分割します。ワークショップを簡潔にするため、フィルター機能と品質改善の作業は、同じセッションとブランチで進めて 1 つの PR にまとめます。

このレッスンでは、次のことを行います。

- Agent Merge と、マージ ライフサイクルを自動化する方法を学びます。
- 機能 PR 全体と検証の証拠を確認します。
- レビュー後にのみ Agent Merge に許可を与え、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローでは、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys は、マージの許可を開発者が管理しながら、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするまでの残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み込み、失敗した継続的インテグレーション (CI) チェックの修正、レビュー コメントへの対応、必要な場合のリベースなど、マージを妨げる問題に対処します。GitHub が許可すると、PR をマージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストがマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge に任せることもできますが、コードの編集やマージには、引き続き明示的な許可が必要です。マージの許可を与える前に、許可する操作と作業の内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したので、Agent Merge に PR の残りの処理を任せます。

1. エージェント ピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンの選択だけでは開始されません。

Agent Merge が開始され、次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、PR の説明本文で関連する issue を参照します。
- ターゲット ブランチにリベースし、必要に応じてマージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot code review からのフィードバックを確認し、コメントを解決するための変更を行います。
- 必要に応じて、すべてのチェックが成功した後に PR を自動的にマージします。

すべての条件を満たした後、Agent Merge に PR をマージさせます。

5. マージを許可する前に、PR の差分と検証の証拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** にチェックが付いていることを確認します。
8. 次のように明示して、エージェントにマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進行状況を確認し、報告された問題を解決します。続行する前に PR の状態が **Merged** であることを確認してください。マージの許可を有効にしたことやエージェントが動作中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。作業を続ける前に、その問題を解決してください。
